## What's in the MCP — 15 tools, all wired

Tools are namespaced `mcp__crema-catalog-ops__crema_*`. They appear at session start once the MCP is loaded.

### Read-only (safe to call freely)
| Tool | Purpose |
|---|---|
| `crema_list_roasters` | Substring search across 96 published roasters; returns slug + name + city + state + website + products_count |
| `crema_get_all_status` | Orchestrator dashboard: per-roaster snapshot age + diff counts. Filters: has_diff, has_snapshot, platform, missing_article_hint |
| `crema_get_snapshot` | One roaster's snapshot + diff vs prev + breakdown (storefront / in_catalog / unknown) |
| `crema_list_proposals` | Scrape proposals queue (pending / applied / rejected) |
| `crema_get_hints` | All 3 site quirks for a roaster (bio+bean, journal, diff) |
| `crema_list_jobs` | Recent catalog-ops jobs (scrape, article_scrape, roaster_enrich) |
| `crema_list_agent_runs` | The audit log. Filter by agent_identity / tool_name / session_id |

### Mutating (idempotent — crawl + snapshot only, no LLM)
| Tool | Purpose |
|---|---|
| `crema_sync_roaster` | Crawl + snapshot ONE roaster. Modes: `tab1` (full re-baseline) / `tab2` (diff vs prev). Zero LLM cost. |
| `crema_sync_all` | Bulk crawl every roaster in parallel background tasks. Returns immediately. |

### LLM work (real cost — bio Sonnet + per-product/article Haiku)
| Tool | Purpose |
|---|---|
| `crema_enrich_roaster` | Full pipeline for ONE roaster: bio Sonnet + catalog scrape (Haiku per-product) + article scrape (Haiku per-article). |
| `crema_enrich_all` | Bulk full-pipeline refresh. Pass `slugs` or `filter` (has_diff / missing_article_hint / ...). **This is the tool that runs the actual LLM enrichment.** WARNING: ~$0.10-1.00 per roaster — fanning out to all 96 is real money. |

### Proposals queue
| Tool | Purpose |
|---|---|
| `crema_approve_proposals` | Approve by id — merges to live `products` table |
| `crema_reject_proposals` | Reject by id — discards pending |

### Hints
| Tool | Purpose |
|---|---|
| `crema_set_diff_hint` | Admin-write the diff quirk (the ONLY hint that's admin-written; bio + journal are auto-generated by Sonnet meta-calls) |
| `crema_regenerate_hint` | Flag bio (one-shot) or journal (perpetual) for regeneration on the next enrich run |

## Known quirks + bugs to fix

### Quirk-card status pill bug (Task #6 from this session)
On `/admin/refresh/[slug]`, the Bio + bean quirk and Journal quirk cards show "Not generated yet" pill when `*_updated_at` is null, even if the `*_hint` column has content. The pill should check content presence (`hint != null`), not the timestamp column.

Fix is one line in [crema-app/app/admin/refresh/[slug].tsx](crema-app/app/admin/refresh/[slug].tsx) per card. Look for the conditional that renders the "Not generated yet" subtitle.

### `_diff(cur, prev=null)` returns `bio_changed=true` for first-ever sync
In [services/sync_runner.py](Community/coffee-community-api/services/sync_runner.py)'s `_diff()` function, when prev is None (first sync), the diff is set to `bio_changed=True` and all products as "added". This is intentional ("everything is new" signal) but trips orchestrator filters: `crema_get_all_status({has_diff: true})` returns 93/96 roasters even though most have no actual changes.

The fix is to special-case `has_prev=False` in the orchestrator filter logic (the `totalDiff` calc on either client or server side), or to make `_diff` return `has_diff=false` when there's no prev (treat first-sync as "baseline established, no diff to compute"). Latter is cleaner.

### Agent activity admin view doesn't exist yet
The `agent_runs` table is populated but no admin UI surfaces it. LAUNCH_TODO §3.10.3 captures this — clone the orchestrator surface pattern (filter + list + drill-in) for the audit log.

## Architecture memory (saved in memory dir)

`/Users/swarajnanda/.claude/projects/-Users-swarajnanda-Coffee-Aggregator/memory/feedback_agent_first_orchestration.md` captures the agent-first vision:

> Crema is built as an agent-first organization. Routine operational work — refreshing a roaster's catalog, moderating the feed, ad-placement curation, journal curation — is performed by agents, not by humans clicking through admin UI. Humans (or Claude as orchestrator) only do the orchestrator's job: scope selection, diff review, approve/reject.
>
> Two interchangeable invocation paths share prompts + schemas: (a) Anthropic SDK call (paid by user), (b) Claude Code Agent fallback (paid by my agent budget). Same prompt + schema = same output. The SDK is the billing surface, not the architecture.

The MCP server is the agent-native interface. The web UI is the human-native interface. Same backend, two clients. See LAUNCH_TODO §3.10 for the cloud-deployment items that complete the picture (HTTP transport, provider abstraction, audit visibility, scheduled digests).
